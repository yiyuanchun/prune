## 一、当前背景

原始网络首先经过：

```text
原始网络
  ↓
恒不激活 ReLU 剪枝
  ↓
恒激活 ReLU 重构
  ↓
得到规模更小但保持等价的神经网络
```

后续将这个网络称为：

```text
less_neuron_network
```

当前项目之后大致执行：

```text
less_neuron_network
  ↓
处理最后两个隐藏层
  ↓
classify_or_split_layer
  ↓
神经元被标记为 inc / dec
  ↓
混合单调性的神经元 split
  ↓
相同 label 的神经元进行 LP Merge
  ↓
Merge 到目标大小（当前通常为初始大小的 50%）
  ↓
CEGAR / PGD / refinement / formal verification
```

当前存在一个问题：

某些隐藏层虽然最终未必需要进行大量 Merge，但提前进行了 inc/dec preprocessing 和 split。

split 可能导致神经元数量增加，同时增加后续 CROWN、LP Merge、network reconstruction 和 refinement 的开销。

因此希望把当前“一次性处理固定数量隐藏层”的策略修改为：

# 渐进式、从输出端向输入端逐层扩展的 preprocessing + Merge 策略

核心原则：

> 只有真正准备执行 Merge 的隐藏层，才进行 inc/dec classification / split。

未进入当前 Merge 范围的隐藏层不要提前进行等价性划分和 split。

---

# 二、新算法总体设计

从：

```text
less_neuron_network
```

开始，在后续等价性预处理流程外增加一层“逐层扩展”的循环。

假设网络共有 N 个隐藏层。

处理顺序必须是：

```text
最后隐藏层
↓
倒数第二隐藏层
↓
倒数第三隐藏层
↓
...
```

每一轮只新增一个“当前探索层”。

已经在前一轮证明可以安全执行到目标 Merge 比例的层，在下一轮可以直接重现对应 Merge 过程，而不需要每两次 Merge 再执行 random test。

---

# 三、第 1 轮

第 1 轮必须从干净的：

```text
less_neuron_network
```

开始。

只对：

```text
最后一个隐藏层
```

进行 inc/dec preprocessing。

具体流程：

```text
less_neuron_network
        ↓
只对最后隐藏层执行 classify_or_split_layer
        ↓
单一方向神经元：
    只标记 inc 或 dec

混合方向神经元：
    split 成 inc + dec
        ↓
仅允许相同 inc/dec label 的 neuron pair Merge
```

然后开始 LP Merge。

目标大小仍然暂时保持现有逻辑：

```text
target_size = ceil(0.5 * reference_size)
```

但是不要连续 Merge 到 50%。

改为：

```text
Merge 2 次
↓
执行一次 random property test
↓
判断当前 Merge 后网络是否已经存在 property violation
```

如果 random test 发现 violation：

```text
立即停止该层继续 Merge
```

不要为了达到 50% 而继续执行剩余 Merge。

然后：

```text
保留当前 Merge 状态
↓
结束渐进式 preprocessing
↓
进入现有的后续 CEGAR / PGD / refinement / verification 流程
```

注意：

这里 random test 不再只是日志。

它必须真正作为：

```text
early stop condition
```

控制 Merge 是否继续。

---

如果：

```text
每两次 Merge → random test
```

始终没有发现 violation，并且最终成功将最后隐藏层 Merge 到目标 50%，则认为：

```text
最后隐藏层已经完成本轮探索
```

记录：

```text
该层可以 Merge 到 50%
```

然后进入第 2 轮。

---

# 四、第 2 轮

第 2 轮必须重新从：

```text
less_neuron_network
```

开始构建本轮网络。

不要直接在第 1 轮已经 Merge 完成的 state 上继续向前处理。

这是非常重要的要求。

第 2 轮需要处理：

```text
最后两个隐藏层
```

顺序仍然必须从后往前：

```text
最后隐藏层
↓
倒数第二隐藏层
```

首先重新执行必要的 inc/dec preprocessing。

因为倒数第二隐藏层的 inc/dec 判断依赖最后隐藏层已经确定的 inc/dec labels，所以不要破坏当前从后往前传播单调性标签的逻辑。

第 1 轮已经确认：

```text
最后隐藏层可以 Merge 到 50%
```

因此第 2 轮中：

```text
最后隐藏层：
    可以直接执行对应 Merge
    直到达到 50%
    中间不需要每两次 Merge 做 random test
```

然后开始处理：

```text
倒数第二隐藏层
```

这是本轮新的“探索层”。

执行：

```text
倒数第二隐藏层
↓
classify_or_split_layer
↓
LP Merge × 2
↓
random test
↓
如果没有 violation → 继续
↓
LP Merge × 2
↓
random test
...
```

如果中途发现 violation：

```text
立即停止倒数第二隐藏层继续 Merge
↓
不再尝试更前面的隐藏层
↓
进入现有 refinement / verification 流程
```

如果倒数第二隐藏层也成功 Merge 到 50%，并始终没有 random violation：

```text
记录最后两个隐藏层均可 Merge 到 50%
↓
进入第 3 轮
```

---

# 五、第 3 轮以及后续轮次

按照完全相同的模式继续。

例如第 3 轮：

```text
重新从 less_neuron_network 开始

最后隐藏层
    → 已确认
    → 直接 Merge 到 50%

倒数第二隐藏层
    → 已确认
    → 直接 Merge 到 50%

倒数第三隐藏层
    → 当前探索层
    → 每完成 2 次 Merge 做一次 random test
```

如果倒数第三隐藏层：

```text
中途出现 random violation
```

则：

```text
停止继续 Merge
↓
停止向更前面的隐藏层扩展
↓
进入 refinement / verification
```

如果：

```text
倒数第三隐藏层成功 Merge 到 50%
且始终没有 violation
```

则：

```text
进入第 4 轮
```

以此类推，直到：

1. 某个新探索层在 Merge 过程中出现 random violation；

或者：

2. 所有允许处理的隐藏层都已经探索完毕。

# 七、最重要的设计原则

必须保证：

```text
没有准备进行 Merge 的隐藏层
↓
不要执行 classify_or_split_layer
↓
不要提前 split 神经元
```

即：

```text
只有真正进入本轮 Merge 范围的隐藏层
才进行 inc/dec preprocessing
```

这是本次修改最核心的目标。

不要在每一轮开始时对所有隐藏层统一执行 inc/dec preprocessing。

# 八、关于 inc/dec preprocessing

请保留当前算法的单调性语义。

即：

对于某个隐藏层神经元：

### 只有 increasing influence

```text
直接标记 inc
```

不要 split。

### 只有 decreasing influence

```text
直接标记 dec
```

不要 split。

### 同时存在 increasing 和 decreasing influence

才：

```text
split 成 inc neuron + dec neuron
```

并保持当前 outgoing edge 拆分语义。

同时继续保证：

```text
只有相同 inc/dec label 的神经元
才允许进入 Merge pair
```

不要改变这一 soundness 相关约束。

---

# 九、关于 random test

当前项目中 random test 很多时候只是记录：

```text
random_violation_ignored_until_target
```

新的实现中不要再忽略探索层中途出现的 random violation。

对于当前 exploration layer：

```text
每成功完成 2 次 Merge
```

执行一次已有的：

```text
_random_property_violation_test(...)
```

如果：

```text
has_violation == True
```

必须立刻：

```text
停止当前 exploration layer 的后续 Merge
```

并结束外层逐层扩展。

然后使用当前状态进入：

```text
PGD
CEGAR
refinement
formal verification
```

不要因为 random test 本身不是正式证明工具而错误地把该样本直接标记为 UNSAFE。

random test 在这里的作用仅仅是：

```text
停止进一步 abstraction / Merge
```

而不是直接决定最终 verification_result。

最终安全性结论仍然必须由原来的 CEGAR / counterexample validation / formal verification 流程决定。

# 十、处理奇数次 Merge 的情况

如果当前探索层距离 target_size 剩余的 Merge 次数不是 2 的整数倍，例如最后只剩：

```text
1 次 Merge
```

则应该：

```text
完成最后 1 次 Merge
↓
立即执行一次 random test
```

也就是说：

random test 的条件应当是：

```text
每完成 2 次 Merge

或者

已经达到当前层 target_size
```

二者满足任一条件就测试。

避免最后一次 Merge 后没有检查。

# 十三、停止条件

外层逐层循环存在以下停止条件。

### 条件 1：探索层出现 random violation

```text
stop progressive preprocessing
↓
使用当前 round_state
↓
进入原来的 CEGAR 后续流程
```

### 条件 2：探索层已经 Merge 到 target_size

```text
本层标记为 confirmed
↓
开始下一轮
```

### 条件 3：所有目标隐藏层均已经处理

```text
停止 progressive preprocessing
↓
使用最后一轮 state
↓
进入后续 verification
```

### 条件 4：当前层没有合法的 same-label merge pair

保留当前已有语义，不强制 Merge。

记录停止原因，并合理结束当前层探索。
