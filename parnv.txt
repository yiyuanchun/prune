==================================================
三、流程 1：REDNet + NARv-like CEGAR
==================================================

流程 1 的完整执行顺序必须为：

Original FC ReLU Network N
        │
        │ Property P 对应的输入区间
        ↓
      CROWN
        │
        ├── Stable inactive ReLU
        │        ↓
        │      exact deletion
        │
        └── Stable active ReLU
                 ↓
        affine contribution folding
                 ↓
        reconstruct fewer stable ReLUs
                 ↓
             REDNet N_R

要求：

N_R(x) = N(x), ∀x ∈ P

也就是说 REDNet 阶段必须是 exact reduction，
不能引入 abstraction error。

然后：

REDNet N_R
        ↓
当前项目的 NARv-like CEGAR
        ↓
inc/dec preprocessing
        ↓
Merge
        ↓
Marabou
        ↓
如果得到 counterexample：
        ↓
在原始/具体网络上判断是否为真实反例
        ↓
如果是 spurious counterexample：
        ↓
refinement
        ↓
继续验证

注意：

1. Stable inactive ReLU 删除继续使用当前项目已有的 CROWN bound。
2. Stable active ReLU reduction 必须依据我提供的 REDNet 论文实现。
3. 如果项目中已经存在 stable-active folding/reconstruction 代码，请先审查正确性，不要重复实现。
4. 如果代码存在 bug，请修改。
5. 必须保证 REDNet reduction 后网络与 reduction 前网络在当前 property 输入区间内保持等价。
6. 不允许把 approximate abstraction 当作 REDNet exact reduction。

==================================================
七、REDNet 前后输出变化的计算方式
==================================================

这一部分必须严格统一，避免得到没有意义的数据。

在每个 property 的输入区域 P 内随机采样若干输入，例如：

128 个样本

对于每个输入 x：

y_original = N(x)
y_rednet   = N_R(x)

定义每个采样点的输出误差：

e(x) = max_i |y_original_i - y_rednet_i|

也就是输出向量的 L∞ absolute error。

对全部采样点的 e(x) 计算：

mean_error
variance_error
max_error

CSV 中记录：
equivalence_output_abs_error_mean
equivalence_output_abs_error_variance
equivalence_output_abs_error_max

注意：

不要计算 signed difference 的均值，因为正负误差会抵消。
必须计算 absolute error。
理论上 REDNet 是 exact reduction，所以这些误差应非常接近浮点误差，例如：

10^-6 ~ 10^-12
具体阈值根据当前 float 精度确定。
如果误差明显偏大：
不要继续跑正式实验。
必须先排查 REDNet 实现是否存在错误。

十一、代码修改原则
==================================================

在运行之前请先仔细审查代码。

重点检查：

1. MNIST 64x3 ONNX 网络是否能够正确转换/读取。
2. property 构造是否正确：
   epsilon = 0.02。
3. CROWN bound 是否针对当前 property 输入区间计算。
4. stable inactive 判断是否正确。
5. stable active 判断是否正确。
6. stable active reconstruction 是否严格保持等价。
7. reconstruction 后权重矩阵、bias 和下一层连接维度是否正确。
8. `.onnx` / `.nnet` 转换是否会改变输出。
9. NARv-like CEGAR 是否真正接收到 REDNet 后的网络，而不是又重新读取原始网络。
10. genuine/spurious counterexample 判断是否仍然以正确的 concrete network 为基准。
11. refinement 后的网络是否仍然符合当前 reduction / abstraction 映射关系。
12. CSV 中统计的时间范围是否一致。

禁止为了让程序“跑通”而吞掉异常。

如果出现 ERROR：

CSV 要记录 ERROR，
日志中保留完整 traceback。
